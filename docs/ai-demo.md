# OCR และ AI Chat Assistant — Demo

เพิ่มเมื่อ 4 ตุลาคม 2026 โดยใช้ธีมและองค์ประกอบ Lovable เดิม ไม่เพิ่มบริการภายนอกหรือ dependency

## ทดลอง OCR

1. เปิด Booking → Customer & Documents → OCR Document Review
2. เลือกบัตรประชาชน ทะเบียนบ้าน หรือหลักฐานชำระเงิน และกรณีสาธิต: ถูกต้อง / อ่านไม่ชัด / บัตรหมดอายุ / ข้อมูลไม่ตรงการจอง
3. ใช้เอกสารตัวอย่าง หรือเลือก JPG, PNG, WebP, PDF ขนาดไม่เกิน 10 MB แล้วกดตรวจเอกสารจำลอง รูปภาพแสดงตัวอย่างจากเครื่อง ส่วน PDF แสดงชื่อและขนาดไฟล์
4. ตรวจผลอ่านและความมั่นใจรายช่อง แก้ข้อความที่ผิด ช่องความมั่นใจต่ำกว่า 80% ต้องทำเครื่องหมายตรวจแล้ว วันที่ผิด บัตรหมดอายุ ชื่อ/เลขบัตรหรือเลข Booking/ยอดเงินไม่ตรงจะบล็อกการยืนยัน
5. ยืนยันเอกสาร ระบบเก็บผู้ตรวจ เวลา ผลที่ยืนยัน และ Activity History/Audit Log การแก้ไขโดยผู้ใช้คงค่าความมั่นใจ OCR เดิม

เฉพาะบัตรประชาชนที่ยืนยันจึงผ่านเงื่อนไข OCR ของ Workflow การยืนยันทะเบียนบ้านหรือหลักฐานชำระเงินไม่ยืนยันตัวตนแทนบัตรและไม่บันทึกรับเงิน หาก OCR จำลองขัดข้อง ให้ Retry รายการ OCR ใน Integrations แล้วกลับมาตรวจอีกครั้ง

**Demo ไม่อ่านเนื้อหาไฟล์จริง** ผลอ่านมาจากข้อมูลการจองและกรณีที่เลือก ไฟล์ไม่ส่งออกจากเครื่องและไม่เก็บใน local storage เก็บเฉพาะข้อมูลผลอ่านจำลอง ข้อมูลและสิทธิ์ยังเป็นต้นแบบในเบราว์เซอร์

## ทดลอง AI Chat

กด AI Assistant มุมขวาล่างจากทุกหน้า ถามงานวันนี้/พรุ่งนี้/เกินกำหนด รถพร้อมขายที่มี Bonus การจองใกล้หมดอายุ Commission คืนเงิน Loyalty วิธีตรวจ OCR หรือเลข Booking ได้ เมื่ออยู่หน้ารายละเอียด Booking ใช้ “สรุปการจองนี้” เพื่ออ่านสถานะปัจจุบัน

คำตอบแนบลิงก์เปิดรายการที่เกี่ยวข้องตามเมนู บทบาท สาขา และขอบเขต Sales ของผู้ใช้ ผู้ช่วยอ่านข้อมูลสรุป ไม่สร้าง แก้ไข อนุมัติ หรือจ่ายเงิน บริบทไม่รวมเลขบัตร เบอร์โทร ต้นทุน หรือเนื้อหาเอกสารดิบ

ใช้ “จำลอง Chat Error ครั้งถัดไป” แล้วส่งคำถามเพื่อลอง Error/Retry ปุ่มลองคำถามเดิมไม่สร้างข้อความผู้ใช้ซ้ำ Enter ส่งคำถาม Shift+Enter ขึ้นบรรทัดใหม่ “เริ่มแชตใหม่” ล้างบทสนทนาและยกเลิกคำขอที่ค้าง

**Chat Demo ใช้คำตอบที่เตรียมไว้ ไม่ใช่โมเดล AI จริง** ไม่ส่งข้อความหรือข้อมูลไปบริการภายนอก บทสนทนาเก็บในหน่วยความจำและเริ่มใหม่เมื่อ reload หรือเปลี่ยนบทบาท สาขา หรือการตั้งค่าสิทธิ์

## จุดเชื่อม API จริง

แยก UI จาก provider ไว้แล้ว:

- `src/lib/ai/types.ts`: สัญญา `DocumentProvider.analyze(request, signal)` และ `ChatProvider.reply(request, signal)` พร้อม structured request/response
- `src/lib/ai/providers.ts`: adapter จำลองที่ UI เรียก เปลี่ยน implementation เป็น server-backed adapter ได้
- `src/lib/ai/documents.ts`: การตรวจไฟล์ ตรวจผลอ่าน และบันทึกผลยืนยันโดยผู้ใช้
- `src/lib/ai/context.ts`: ข้อมูลสรุปที่เลือกเฉพาะฟิลด์และรายการตามสิทธิ์
- `src/components/app/DocumentReview.tsx` และ `AIChatAssistant.tsx`: Loading, Error, Retry, cancellation และการแสดงผล

OCR request มี `file?: File` เป็นข้อมูลชั่วคราวสำหรับ adapter ในอนาคต Demo ไม่อ่านไฟล์นี้ Server adapter สามารถส่ง multipart ไป endpoint ของแอปและแปลงผลบริการเป็น `DocumentAnalysis` (`provider: "api"`) โดยไม่บันทึก File ลง Booking ส่วน Chat ส่ง `ChatRequest` แล้วรับข้อความ references และ suggestions ตาม `AssistantReply`

ก่อนเปิดบริการจริง ต้องเพิ่ม endpoint และ authentication ฝั่ง Server ตรวจสิทธิ์และสร้าง context ซ้ำจากแหล่งข้อมูลที่เชื่อถือได้ ไม่เชื่อ branch/role/context จากเบราว์เซอร์ เก็บ API key เฉพาะฝั่ง Server ตรวจ signature/ขนาดไฟล์และ structured response บังคับรายการอ้างอิงให้อยู่ในขอบเขตสิทธิ์ แยกข้อความหรือเนื้อหาเอกสารออกจากคำสั่งระบบ และใช้ timeout/AbortSignal จัดการคำขอ การยืนยัน OCR และงานอนุมัติยังต้องผ่านผู้ใช้และ validation ของระบบ

ยังไม่มี endpoint, API key, production authentication หรือการเรียกบริการจริงในรอบนี้
