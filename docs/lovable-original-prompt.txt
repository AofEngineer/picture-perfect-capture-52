สร้าง Web Application Prototype สำหรับระบบบริหารการขายรถยนต์หลายสาขา ครอบคลุมการจองรถ ลูกค้า สต็อกรถ ป้ายแดง งานดูแลรถ Loyalty และ Commission

เป้าหมาย:
สร้างต้นแบบที่ดูเหมือนระบบพร้อมใช้งานสำหรับนำเสนอผู้บริหารและผู้ใช้งานจริง มีข้อมูลตัวอย่างที่เชื่อมโยงกัน และสามารถคลิกสาธิตกระบวนการสำคัญได้ตั้งแต่ต้นจนจบ

ใช้ภาษาไทยเป็นหลักใน UI และใช้ชื่อเมนูหลักเป็นภาษาอังกฤษตามที่กำหนด
ทุกระบบภายนอก เช่น OCR, E-Signature, Loyalty และ AMLO ให้จำลองการเชื่อมต่อ พร้อมแสดงป้าย “ข้อมูลจำลอง / Demo” อย่างชัดเจน
ผลการตรวจสอบ AMLO ในต้นแบบต้องระบุว่าเป็นผลจำลอง ไม่ใช่ผลตรวจสอบจริง

==================================================
1. รูปแบบและโครงสร้าง UI
==================================================

ออกแบบเป็น Enterprise Dashboard สำหรับธุรกิจรถยนต์:
- เรียบหรู อ่านง่าย ใช้งานสะดวก
- ใช้สี theme ของ web BMW
- ใช้ status badge พร้อมข้อความ ไม่สื่อสารสถานะด้วยสีอย่างเดียว
- ตารางรองรับ Search, Filter, Sort และ Pagination
- แสดงตัวเลขเงินเป็นบาทและวันที่ในรูปแบบไทย
- รองรับ Desktop เป็นหลัก และ Responsive บน Tablet
- ใช้ Drawer สำหรับดูรายละเอียดเร็ว และหน้ารายละเอียดเต็มสำหรับงานซับซ้อน
- มี Loading, Empty, Error และ Success State
- ฟอร์มมี Validation และข้อความผิดพลาดที่เข้าใจง่าย

Layout:
- Sidebar สำหรับเมนูหลัก
- Top bar มีตัวเลือกสาขา ช่องค้นหากลาง Notification Center และโปรไฟล์ผู้ใช้
- Breadcrumb แสดงตำแหน่งหน้าปัจจุบัน
- ผู้ใช้เห็นข้อมูลตามตำแหน่งและสาขาที่ได้รับสิทธิ์
- มีตัวเลือกสลับบทบาทสำหรับสาธิต โดยระบุว่าเป็น Demo Role Switcher

เมนูหลักต้องเรียงตามนี้:
1. Dashboard
2. Booking
3. Customer
4. Stock
5. Sales

เมนูรองในส่วน Administration:
- Reports
- Integrations
- Loyalty Configuration
- Access Control
- Audit Log
- Notification Settings

Service Order และ Red Plate Management ให้อยู่ภายใต้ Stock
การคืนเงินและการออกเอกสารการขายให้อยู่ภายใต้ Booking
Commission ให้อยู่ภายใต้ Sales

==================================================
2. Dashboard
==================================================

แสดงภาพรวมตามสาขาและสิทธิ์ของผู้ใช้:
- จำนวนการจองที่กำลังดำเนินการ
- รถพร้อมขาย
- นัด Test Drive
- นัดส่งมอบรถ
- งานเกินกำหนด
- คำขอคืนเงินรออนุมัติ
- ป้ายแดงที่ต้องติดตามคืน
- Commission รอส่งเบิกหรือรออนุมัติ

To-do List รายสัปดาห์:
- สลับมุมมอง List / Weekly Calendar
- เลือกสัปดาห์และกรองผู้รับผิดชอบ สาขา และประเภทงาน
- ตัวอย่างงาน: นัด Test Drive, นัดส่งมอบรถ, ติดตามเอกสาร,
  ติดตามชำระเงิน, คืนป้ายแดง และดูแลรถก่อนส่งมอบ
- แสดงวันเวลา ลูกค้า รถ ผู้รับผิดชอบ และสถานะ
- สถานะ: ยังไม่เริ่ม / กำลังดำเนินการ / รอข้อมูล / เสร็จสิ้น / เกินกำหนด
- เปิดรายละเอียดงาน เปลี่ยนสถานะ มอบหมายงาน และเลื่อนนัดได้
- คลิกงานเพื่อไปยัง Booking, Customer หรือ Service Order ที่เกี่ยวข้อง

เพิ่มส่วน “งานที่ต้องทำวันนี้” และ “งานวันพรุ่งนี้”
เพิ่มส่วน “งานคงค้างตามขั้นตอน” เพื่อดู bottleneck ของ workflow

==================================================
3. Booking
==================================================

หน้ารายการจอง:
- ค้นหาด้วยเลขการจอง ชื่อลูกค้า เบอร์โทร VIN และชื่อ Sales
- กรองตามสาขา สถานะ ช่วงวันที่ และผู้รับผิดชอบ
- แสดงเลขการจอง ลูกค้า รถ สาขา Sales วันที่จอง เงินจอง
  วันหมดอายุการจอง นัดส่งมอบ และสถานะ
- สร้างการจองใหม่ และเปิดรายละเอียดการจองได้

หน้ารายละเอียดการจองมี Tabs:
- Overview
- Customer & Documents
- Payment & Loyalty
- Workflow & Tasks
- Contracts & Delivery
- Refund
- Activity History

Workflow การขาย:
สร้างการจอง → ตรวจสอบข้อมูลและเอกสาร → ตรวจสอบ AMLO
→ ทำสัญญาและลงนาม → ชำระเงิน/ใช้ Point
→ เตรียมรถและตรวจ Checklist → ส่งมอบ → ปิดการขาย

แต่ละขั้นตอนแสดง:
- ผู้รับผิดชอบ
- วันครบกำหนด
- สถานะ
- เอกสารหรือข้อมูลที่ยังขาด
- งานที่ต้องทำต่อ
- ประวัติการเปลี่ยนสถานะ

รองรับการมอบหมายงาน การติดตามงานค้าง และการแจ้งเตือน
เงื่อนไขที่ต้องทำให้ครบก่อนผ่านแต่ละขั้นตอนให้เป็นค่าที่ปรับได้ในต้นแบบ

การหมดอายุและหลุดจอง:
- ตั้งวันหมดอายุและเงื่อนไขตามข้อตกลงได้
- แสดง Countdown และเหตุผลที่หลุดจอง
- เมื่อหลุดจอง ให้สร้างงานติดตามและตรวจสอบเงินจอง
- แยกสถานะการจองออกจากสถานะรถ
- ระบุชัดเจนว่ารถพร้อมให้จองใหม่หรือยังต้องรอผู้มีสิทธิ์อนุมัติปล่อยรถ

OCR:
- มีพื้นที่ Upload เอกสาร เช่น บัตรประชาชนและเอกสารประกอบการขาย
- จำลองผล OCR พร้อมระดับความมั่นใจรายช่องข้อมูล
- แสดงเอกสารต้นฉบับคู่กับข้อมูลที่อ่านได้
- Highlight ช่องที่ต้องตรวจสอบ
- ผู้ใช้แก้ไขและยืนยันก่อนนำข้อมูลไปใช้
- บันทึกว่าใครเป็นผู้ตรวจและยืนยันข้อมูล
- ใช้ข้อมูลส่วนบุคคลสมมติทั้งหมด

AMLO API:
- ปุ่ม “ตรวจสอบ AMLO”
- จำลองสถานะ: ยังไม่ตรวจ / กำลังตรวจ / ไม่พบรายการตรงกัน
  / ต้องตรวจสอบเพิ่มเติม / ระบบภายนอกขัดข้อง
- แสดงวันเวลา Reference ID และรายละเอียดจำลอง
- มีปุ่ม Retry และสร้างงานให้ผู้รับผิดชอบตรวจสอบเพิ่มเติม
- ห้ามแสดงผลจำลองเป็นการรับรองหรืออนุมัติทางกฎหมาย

E-Signature:
- แสดงเอกสาร ผู้ลงนาม และลำดับการลงนาม
- สถานะ: ร่าง / รอลงนาม / ลงนามบางส่วน / ครบแล้ว / หมดอายุ
- จำลองการลงนามผ่าน Signature Pad หรือชื่อผู้ลงนาม
- แสดงเวลาและประวัติการลงนาม
- หลังลงนามสามารถดูเอกสารตัวอย่างและดาวน์โหลดได้

เอกสารการขายและส่งมอบ:
- มี Document Center ภายในการจอง
- เลือกเอกสาร เช่น ใบจอง สัญญาซื้อขาย ใบรับเงิน
  ใบตรวจรับรถ ใบส่งมอบรถ และแบบฟอร์มยืมป้ายแดง
- ดึงข้อมูลลูกค้า รถ ราคา การชำระเงิน และสาขามาเติมอัตโนมัติ
- Preview ก่อน Print
- มีปุ่ม Print และ Download PDF ตัวอย่างที่ทำงานได้
- เอกสารต้องระบุว่าเป็นเอกสารตัวอย่างสำหรับ Demo
- แสดงสถานะเอกสาร เวอร์ชัน และประวัติการออกเอกสาร

การคืนเงินจอง:
ออกแบบเป็น workflow ที่แตกแขนงตามเงื่อนไข และแสดงสาขาที่รับผิดชอบด้วย

ขั้นตอน:
ขอคืนเงิน → ตรวจสอบเงื่อนไข → อนุมัติ → ดำเนินการคืนเงิน
→ บันทึกหลักฐาน → ปิดคำขอ

แขนงตัวอย่าง:
A. คืนเต็มจำนวน
B. คืนบางส่วน พร้อมรายการหักและเหตุผล
C. ไม่เข้าเงื่อนไขคืนเงิน พร้อมเหตุผลและผลพิจารณา
D. มีการใช้ Loyalty Point ให้แยกส่วนคืนเงินและคืน Point
E. ต้องให้สำนักงานใหญ่หรืออีกสาขาดำเนินการต่อ

แสดง:
- เงินจองเดิม
- จำนวนเงินที่ขอคืน
- รายการหัก
- เงินคืนสุทธิ
- Point ที่เกี่ยวข้อง
- สาขาที่รับเงิน สาขาที่รับผิดชอบคืน และผู้อนุมัติ
- ช่องทางคืนเงินและหลักฐาน
- สถานะและ Timeline

เงื่อนไขทั้งหมดเป็นตัวอย่างที่ปรับได้ ไม่กำหนดเป็นนโยบายตายตัว
เมื่อดำเนินการสำเร็จให้ปรับยอดการชำระเงินและประวัติที่เกี่ยวข้อง
ป้องกันการทำรายการคืนเงินซ้ำจากการกดปุ่มซ้ำ

==================================================
4. Customer
==================================================

หน้ารายชื่อลูกค้า:
- ค้นหาด้วยรหัสลูกค้า ชื่อ เบอร์โทร และเลขสมาชิก
- กรองตามสาขา Sales ผู้ดูแล และระดับสมาชิก
- แสดงข้อมูลติดต่อ ระดับสมาชิก Point คงเหลือ และกิจกรรมล่าสุด

หน้าข้อมูลลูกค้ามี Tabs:
- Profile
- Purchase History
- Visit & Test Drive History
- Bookings
- Loyalty
- Documents
- Activity Timeline

แสดง:
- ข้อมูลลูกค้าและ Sales ผู้ดูแล
- ประวัติการซื้อรถ พร้อมลิงก์ไป Booking และรถ
- ประวัติการเข้าชมและ Test Drive
- นัดหมายครั้งถัดไป
- ประวัติการติดต่อและงานติดตาม
- ระดับสมาชิก Point คงเหลือ Point ใกล้หมดอายุ
- ประวัติ Earn / Burn / Adjust / Reverse

Loyalty:
- แสดง Loyalty Member ID และระบบต้นทาง
- สถานะการเชื่อมต่อและเวลาที่ Sync ล่าสุด
- ปุ่ม Sync ข้อมูลจำลอง
- เปรียบเทียบยอดภายในกับยอดจากระบบ Loyalty
- หากยอดไม่ตรง ให้แสดงสถานะรอตรวจสอบและสร้างงานติดตาม
- ทุกธุรกรรมมี Reference ID ที่เชื่อมกับ Booking

==================================================
5. Loyalty Configuration และการใช้ Point
==================================================

หน้าคำนวณและปรับสูตร Loyalty:
- กำหนดอัตราการได้รับ Point จากยอดซื้อ
- กำหนดยอดที่นำมาคำนวณ และรายการที่ไม่รวม
- กำหนดตัวคูณตามระดับสมาชิก รุ่นรถ หรือแคมเปญ
- กำหนดวันเริ่มใช้และวันสิ้นสุด
- กำหนดวิธีปัดเศษและเพดาน Point
- กำหนดอัตราแลก Point เป็นส่วนลดหรือมูลค่าชำระเงิน
- กำหนดข้อจำกัดการใช้ Point ต่อรายการ

มี Formula Simulator:
- กรอกยอดซื้อ ระดับสมาชิก และแคมเปญ
- แสดงสูตร ขั้นตอนคำนวณ และผลลัพธ์
- เปรียบเทียบสูตรเดิมกับสูตรใหม่ก่อนบันทึก
- แสดงเวอร์ชัน ผู้แก้ไข วันเวลา และสถานะการอนุมัติ
- รายการเดิมต้องอ้างอิงสูตรเวอร์ชันที่ใช้ในวันทำรายการ

ใช้ Point ชำระเงินใน Booking:
- แสดงยอดที่ต้องชำระ Point คงเหลือ และ Point ที่ใช้ได้
- กรอก Point ที่ต้องการใช้
- แสดงมูลค่า Point และยอดเงินที่ยังต้องชำระ
- ตรวจสอบยอดไม่เกิน Point คงเหลือและไม่เกินเงื่อนไขที่กำหนด
- แสดง Confirmation ก่อนทำรายการ
- จำลองการ Burn Point ไปยังระบบ Loyalty
- แสดงสถานะ Pending / Success / Failed / Reversed
- หักยอดในต้นแบบเมื่อธุรกรรมสำเร็จ
- ป้องกันการ Burn ซ้ำและมีการจัดการรายการผิดพลาดหรือยกเลิก

รายงาน Loyalty สำหรับตรวจสอบและวางบิล:
- กรองช่วงวันที่ สาขา และสถานะ
- แสดง Booking ลูกค้า จำนวน Point มูลค่าเงิน
  Reference ID และผลการเทียบยอด
- แสดงยอดรวม รายการตรงกัน รายการคลาดเคลื่อน และรายการรอดำเนินการ
- Export CSV และ Print/Download PDF รายงานตัวอย่าง
- มีหน้า Billing Summary รวมรายการที่ใช้ประกอบการวางบิล

==================================================
6. Stock
==================================================

Submenus:
- Vehicle Inventory
- Sales Stock Check
- Stock Operations
- Service Orders
- Red Plate Management

Vehicle Inventory:
- ค้นหาด้วยยี่ห้อ รุ่น สี VIN และรหัสรถ
- กรองสาขา ปี อายุรถ สถานะ Bonus และช่วง Margin
- สลับ Table View / Card View
- แสดงรูปตัวอย่าง ยี่ห้อ รุ่น สี ปี VIN สาขา
  ราคาขาย Margin อายุรถ สถานะ และ Bonus สำหรับ Sales
- อายุรถคำนวณจากวันรับเข้าจนถึงวันที่ปัจจุบัน
- หากมีการโอนสาขา แสดงทั้งอายุรวมและจำนวนวันที่อยู่สาขาปัจจุบัน

แยกสถานะให้เข้าใจง่าย:
สถานะสต็อก:
- พร้อมขาย
- จองแล้ว
- รอรับเข้า
- อยู่ระหว่างโอนสาขา
- อยู่ระหว่างเตรียมรถ/ดูแลรถ
- ขายแล้ว/ส่งมอบแล้ว

เหตุการณ์ที่เกี่ยวข้อง:
- หลุดจอง พร้อมเหตุผลและวันเวลา

แสดงความพร้อมขายแยกจากสถานะ เพื่อระบุว่ารถพร้อมจองหรือส่งมอบหรือไม่

สำหรับรุ่นรถที่สาขาปัจจุบันไม่มีสินค้า:
- แสดงจำนวนที่สาขาอื่น
- แสดงรถที่กำลังเข้ามาและวันที่คาดว่าจะรับเข้า
- ปุ่มดูรถสาขาอื่นหรือขอโอน
- ใช้สถานะ “สินค้าหมดในสาขานี้” ในมุมมองรุ่นรถหรือผลการค้นหา
- รถที่ขายแล้วคงอยู่ในประวัติและไม่สามารถจองใหม่ได้

หน้ารายละเอียดรถ:
- รูปและข้อมูลรถ
- ยี่ห้อ รุ่น สี ปี VIN
- ต้นทุน ราคาขาย Margin ตามสิทธิ์
- Bonus พร้อมเงื่อนไขและระยะเวลา
- วันรับเข้า อายุรถ และสาขาปัจจุบัน
- Booking ที่เกี่ยวข้อง
- ประวัติการรับเข้าและโอน
- Service Order และ Checklist
- เอกสารและ Activity History

Sales Stock Check:
- ออกแบบสำหรับ Sales ค้นหารถได้รวดเร็ว
- เห็นความพร้อมขาย สาขา วันที่พร้อมส่งมอบ และ Bonus
- ดูรถสาขาอื่นและรถที่คาดว่าจะเข้า
- ปุ่ม “สร้างการจองจากรถคันนี้”
- ส่งข้อมูลรถไปยังฟอร์ม Booking อัตโนมัติ
- ซ่อนต้นทุนและ Margin หากไม่มีสิทธิ์

Stock Operations:
1. รับรถเข้า
   - กรอกหรือจำลอง Import ข้อมูลรถ
   - ตรวจสอบ VIN ซ้ำ
   - ระบุสาขา วันรับเข้า เอกสาร และ Checklist รับรถ

2. โอนรถระหว่างสาขา
   - สาขาต้นทาง/ปลายทาง เหตุผล ผู้ขอ ผู้อนุมัติ และวันคาดว่าจะถึง
   - สถานะ: ขออนุมัติ / อนุมัติ / กำลังโอน / รับแล้ว / ยกเลิก
   - เปลี่ยนสาขาปัจจุบันเมื่อปลายทางยืนยันรับรถ

3. จองรถ
   - ตรวจสอบความพร้อม
   - เชื่อมกับ Booking
   - ป้องกันการจองรถคันเดียวกันซ้ำ

==================================================
7. Service Orders และ Checklist ดูแลรถ
==================================================

หน้ารายการ Service Order:
- เชื่อมกับรถและสาขา
- แสดงผู้รับผิดชอบ วันครบกำหนด และสถานะ
- แยกงานวันนี้ งานวันพรุ่งนี้ และงานเกินกำหนด
- กรองตามรถ สาขา และประเภทงาน

Checklist ตัวอย่าง:
- เปลี่ยนแบตเตอรี่
- ชาร์จแบตเตอรี่
- ถ่ายน้ำมันเครื่อง
- ตรวจสภาพรถ
- ตรวจยางและแรงดันลม
- ทำความสะอาด
- ตรวจความพร้อมก่อนส่งมอบ

แต่ละรายการมี:
- วันนัดหมาย
- ผู้รับผิดชอบ
- สถานะ
- หมายเหตุ
- รูปหรือหลักฐานตัวอย่าง
- เวลาเสร็จจริง
- ผู้ตรวจรับ

แจ้งเตือนงานวันนี้และวันพรุ่งนี้ผ่าน Notification Center
แสดงรายการที่ยังไม่ครบใน Booking ก่อนส่งมอบ
เงื่อนไขการบังคับตรวจครบก่อนส่งมอบให้ปรับได้

==================================================
8. Red Plate Management
==================================================

สร้าง Master Data ป้ายแดง:
- รหัสป้าย หมายเลขป้าย จังหวัด และสาขาเจ้าของ
- สาขาที่เก็บป้ายปัจจุบัน
- สถานะ: พร้อมใช้ / จับคู่แล้ว / รอคืน / อยู่ระหว่างโอน / สูญหาย
- รถ ลูกค้า และ Booking ที่จับคู่อยู่
- วันที่ยืม วันครบกำหนด และจำนวนวันที่ใช้
- สถานะจดทะเบียนและวันที่จดทะเบียนสำเร็จ

รองรับ:
- เพิ่มและแก้ไข Master Data
- Matching ป้ายกับรถ ลูกค้า และ Booking
- Un-Matching พร้อมเหตุผลและข้อมูลผู้ดำเนินการ
- โยกย้ายป้ายระหว่างสาขา
- แจ้งสูญหายพร้อมรายละเอียด
- บันทึกการคืนและตรวจรับ
- ดูประวัติการใช้งาน

ป้องกันการจับคู่ป้ายเดียวกันกับหลายรายการพร้อมกัน
ป้ายสูญหายหรืออยู่ระหว่างโอนต้องไม่พร้อม Matching
Un-Matching ต้องแยกจากการยืนยันว่ารับป้ายคืนจริง
จะเปลี่ยนเป็น “พร้อมใช้” ได้เมื่อมีการตรวจรับคืนแล้ว

หน้า “ติดตามคืนป้ายแดง” มี 2 Tabs:
1. ลูกค้าที่ครบกำหนด 30 วันนับจากวันยืม
2. ลูกค้าที่จดทะเบียนสำเร็จและยังไม่คืนป้าย

แสดง:
- ลูกค้า เบอร์โทร รถ หมายเลขป้าย สาขา
- วันที่ยืม วันครบกำหนด จำนวนวันที่เกินกำหนด
- Sales ผู้รับผิดชอบ
- สถานะการติดตามและวันที่ติดต่อครั้งล่าสุด

มีปุ่ม:
- บันทึกการติดตาม
- นัดคืนป้าย
- ยืนยันรับคืน
- เปิด Customer หรือ Booking ที่เกี่ยวข้อง

สร้าง Notification และ To-do ให้ผู้รับผิดชอบ
ค่าเริ่มต้นติดตามที่ 30 วัน และสามารถปรับจำนวนวันได้

==================================================
9. Sales และ Commission
==================================================

หน้ารายชื่อ Sales:
- ค้นหาด้วยชื่อ รหัสพนักงาน และสาขา
- แสดงยอดขาย จำนวนรถที่ขาย เป้าหมาย และ Commission
- เปิดรายละเอียด Sales ได้

หน้ารายละเอียด Sales:
- Profile
- Bookings & Sales
- Tasks
- Commission
- Bonus
- Claim History

หน้าคำนวณ Commission:
- เลือกช่วงเวลาและ Sales
- แสดงรายการขายที่นำมาคำนวณ
- แต่ละรายการแสดง Booking รถ ราคาขาย
  ฐานคำนวณ อัตรา Commission Bonus รายการปรับ และยอดสุทธิ
- เปิด Calculation Breakdown เพื่อดูสูตรและขั้นตอนคำนวณ
- แสดงเงื่อนไขสิทธิ์รับ Commission เช่น สถานะส่งมอบและการชำระเงิน
- สูตรและเงื่อนไขเป็นค่าตัวอย่างที่ปรับได้
- เชื่อม Bonus กับเงื่อนไขที่แสดงใน Stock
- ระบุเงื่อนไข Bonus ที่ใช้จริงกับรายการขายนั้น

Workflow ส่งเบิก:
ร่าง → ส่งเบิก → ผู้จัดการตรวจสอบ → ฝ่ายการเงินอนุมัติ
→ จ่ายแล้ว

แสดง:
- ผู้ตรวจและผู้อนุมัติ
- หมายเหตุหรือเหตุผลตีกลับ
- เอกสารประกอบ
- เลขที่ใบเบิกและวันที่จ่าย

มีปุ่ม:
- Preview ใบเบิก
- ส่งเบิก
- อนุมัติ/ตีกลับตามสิทธิ์
- Export CSV
- Print/Download PDF ตัวอย่าง

Sales เห็นข้อมูลของตนเอง
ผู้จัดการเห็นทีมและสาขาที่ได้รับสิทธิ์
ฝ่ายการเงินเห็นรายการที่ต้องตรวจและจ่าย

ตัวอย่าง:

- Service Order วันนี้และวันพรุ่งนี้

- จดทะเบียนสำเร็จแต่ยังไม่คืนป้าย

- สาขา

- บทบาท/ผู้ใช้/สาขาที่รับแจ้ง
- ความถี่
- เปิด/ปิด Rule
- Preview ตัวอย่างข้อความ

ป้องกันการสร้างแจ้งเตือนซ้ำจากเหตุการณ์เดียวกัน
ในต้นแบบใช้ In-app Notification เป็นหลัก

14. Mock Data และความเชื่อมโยง

- ลูกค้าอย่างน้อย 15 ราย
- Booking อย่างน้อย 12 รายการในขั้นตอนต่างกัน
- Sales อย่างน้อย 6 คน
- ป้ายแดงอย่างน้อย 12 ป้าย
- Service Order อย่างน้อย 8 รายการ

- คืนเงินเต็มจำนวนและบางส่วน
- รายการคืนเงินที่มี Point เกี่ยวข้อง
- รถพร้อมขายพร้อม Bonus
